# 大语言模型和传统 NLP 模型有什么区别？
1、传统 NLP 是「一任务一模型」，分词、命名实体识别、情感分析、问答各训各的，每个模型只会干自己那点事。LLM 是「一个模型干所有事」，因为它在预训练阶段学的是「预测下一个 token」这件最通用的事，下游任务用 Prompt 表达就行，不用再分别训练。

2、传统 NLP 模型是判别式的，吃一段文本输出一个标签或概率；LLM 是生成式的，吃一段文本输出更多文本，理解和生成在同一个模型里完成。

3、规模到了一定程度，LLM 会「涌现」出训练目标里没有显式教过的能力，比如多步推理、上下文学习、跨语言迁移，这种「量变到质变」的现象在传统 NLP 模型上是看不到的。

# 讲 Transformer 架构基本原理？Encoder 和 Decoder 是什么？
Transformer 最核心的创新是 Self-Attention，让每个 token 都能直接和序列里任意其他位置建立联系，一次性并行计算，彻底解决了 RNN 顺序计算慢、长距离信息衰减的两个老问题。

Encoder 是双向的，每个词能同时看前后文，适合做「理解」类任务

Decoder 是单向的，只能看前面的词，天然适合「生成」任务

# 为什么注意力计算要除以$\sqrt{d_k}$
在注意力机制中，Q 和 K 做点积时，点积结果的尺度会随着维度$d_k$增大而增大。除以 $\sqrt{d_k}$的主要目的，就是把这个尺度稳定下来，避免 Softmax 过早饱和。

# 多头注意力和单头注意力的区别
单组 Q/K/V 只能学习到一种「关联关系」，但语言中的关联是多维度的。「我」和「吃」是主谓关系，「苹果」和「吃」是宾动关系，「苹果」和前文的「苹果树」是指代关系，这些不同类型的关联需要不同的「注意力头」来捕捉

Multi-Head Attention 就是把 Q/K/V 投影到多个不同的子空间（比如 8 个或 32 个头），每组独立计算注意力，最后把所有头的输出拼接起来。每个头可以专注于捕捉不同类型的语言关联，整体上表达能力更强。

# 多头注意力（MHA）有哪些局限？
1、「**显存爆炸**」。推理时每个 head 都要为序列里所有 token 保存自己的 K 和 V 矩阵，这就是 KV Cache。头数越多、序列越长，显存占用越夸张。

2、「**访存慢**」。Attention 计算里 softmax 那步要把整个 N×N 的注意力矩阵搬来搬去，频繁读写 GPU 显存，瓶颈不在算力而在「内存带宽」

3、「**N²** 复杂度」。注意力分数矩阵是 N×N 的，序列翻倍计算量翻 4 倍，长上下文极其昂贵。

# MQA、GQA、Flash Attention 怎么解决？
1、MQA 让所有 head 共享一份 K/V，显存压到 1/H，但表达力损失明显

2、GQA 是折中方案：把 H 个 head 分成 G 组，每组共享一份 K/V

3、Flash Attention不改变 MHA 的结构，而是从计算实现层面把 N×N 的注意力矩阵切成小块、用 GPU 片上缓存做在线 softmax，避免反复读写大矩阵

# 大模型的位置编码是干什么用的？sin/cos、RoPE、ALiBi 有什么区别？
Attention 的计算是对称的，不管词序怎么变，注意力分数都一样。「我打你」和「你打我」对模型来说是一回事，所以必须显式注入位置信息。

1、**sin/cos 绝对位置编码**，给每个位置算一组固定的 sin/cos 值，加到 token embedding 上。**优点**：简单、不需要训练参数。**缺点**：「绝对位置」太死板，模型实际关心的是「相对距离」，而且训练时见过的最长位置之外的位置（比如训练 2K，推理时上 4K），效果会断崖下跌。

2、**RoPE（旋转位置编码）**，「旋转」Q 和 K 向量。每个位置对应一个旋转角度，位置越靠后旋转的角度越大。两个 token 做注意力时，它们 Q/K 的点积自然带上了「相对距离」的信息。

3、**ALiBi（Attention with Linear Biases）**，在注意力分数里加一个「距离惩罚」，离得越远扣分越多，斜率随 head 不同。**优点**：不引入任何可学习参数、长上下文外推天然就好。**缺点**：表达力弱一些，对位置的精细建模不如 RoPE。

# 什么是大模型项目的分词器（Tokenizer）？原理是什么？
模型只能处理整数，不认识字符串，Tokenizer 就是连接人类文字和模型整数世界的桥梁，做两件事：编码（文本 -> token ID 序列）和解码（token ID 序列 -> 文本）。

原理：从小单元出发，反复把出现频率最高的相邻片段合并成新 token，最终形成一个几万到十几万规模的词汇表，既能控制大小又能处理新词。

# 分词器（Tokenizer）的重要性
1、**API 成本估算**，要预估费用，必须用目标模型的 tokenizer 数出来，不能只用字数拍脑袋。

2、**上下文窗口管理**，需要确保输入不超限。但字数和 token 数的比例取决于语言和内容类型，中文 + 代码混合内容很容易让你以为「才 5 万字应该不超」，实际算成 token 已经 8 万了。

3、**避免截断重要信息**，如果你的文档恰好卡在上下文限制边缘，Tokenizer 可能会把一个词从中间硬切开（比如「人工智能」可能被截断成「人工」+ 半个「智」字），导致下游解析或检索失败。

# 大模型是怎么训练出来的？
1、**预训练阶段**：通过大量语料数据对模型进行训练

2、**SFT阶段**：把「续写机器」改造成「对话机器」。数据格式从连续文本变成（指令，期望回答）对，质量比数量重要，几千条精心标注的数据能赢几十万条粗糙数据。

3、**对齐阶段**：让模型的行为更符合人类的价值观和偏好。

# 什么是 Scaling Law？
Scaling Law（缩放定律）讲的是大模型的损失值如何随模型规模、训练数据量、训练算力这三个量变化的可预测关系。

# 大模型的「涌现能力」是怎么回事？
涌现能力（Emergent Abilities） 是 Scaling Law 的一个特殊副产物。当模型规模超过某个临界值（典型是 50B-100B 参数），某些能力会从「完全不能」突变到「能做」：多步推理、上下文学习、跨语言迁移、代码理解等。

# 大模型微调的方案有哪些？
微调的两个正交维度：<br>
改哪些参数：全量微调（全改）、LoRA（改一小部分）、QLoRA（改一小部分 + 量化基础模型）。<br>
学什么目标：SFT（学指令格式）、DPO（学偏好对齐）

**全量微调**：把模型所有参数都拿出来在新数据上继续训练，让所有层都重新适配新任务。**缺点**：模型在新任务上学得好了，原本预训练学到的通用能力反而下降。这是因为所有参数都在被改写，新数据分布有偏的话，模型会忘记原本的「通用知识」。

**LoRA**：冻结原始权重 W 不动，在 W 旁边新增两个小矩阵 A 和 B（维度分别是 d×r 和 r×d，其中 r 远小于 d，通常 r=8 或 16），训练时只更新这两个小矩阵。推理时把 B·A 加回到 W 上，等价于一个全量微调过的模型

**QLoRA**：先把基础模型用 4-bit 量化，然后在量化后的基础模型上套 LoRA。

# 请讲一下 LoRA 技术，除了减少参数量，它还有哪些优点？
1、**推理零开销**，训练完之后，LoRA 的 A、B 两个小矩阵可以直接合并回原始权重，推理阶段完全不需要带额外模块

2、**部署特别灵活**，一个 7B 基础模型才 14GB，每套 LoRA 只有几十 MB，可以同时维护客服、代码、翻译几套 LoRA，按请求类型热切换，不需要为每个场景各跑一个完整模型。

3、**灾难性遗忘风险更低**，因为原始权重全程冻结，只有旁路的小矩阵在学习，相当于在原来知识旁边打补丁，通用能力通常更容易保住。

4、**训练更稳定**，可训练参数少，梯度空间小，对学习率这类超参不那么敏感，调参成本低。

# 主流的 Post-Training 方法有五大类
1、**RLHF**：先用人类对回答的排名训练一个奖励模型，再用 PPO 算法让大模型生成的回答尽量得高分。同时维护一个参考模型用 KL 散度约束，防止主模型「钻空子」。**优点**：效果上限高，**缺点**：流程复杂、要同时维护 4 个模型、训练不稳定。

2、**DPO**：RLHF 的优化目标可以推导成一个等价的监督学习损失，绕过显式奖励模型，直接拿（提示，好回答，差回答）三元组训练。**优点**：只需 2 个模型、训练稳定、实现简单。**缺点**：效果上限依赖偏好数据质量，探索能力不如精心调过的 RL。

3、**GRPO**：砍掉 PPO 的 Value Model，改用「同一问题采样 G 个回答、用组内相对排名作为基线」估计优势函数。

4、**拒绝采样**：让模型对每个 Prompt 生成多个回答，用奖励模型筛出高分的，然后再做一轮 SFT。

5、**RLAIF**：用强 AI 模型代替人类标注偏好

# 大模型生成文本时的解码策略有哪些？贪心、Beam Search、采样分别什么时候用？
确定性策略：<br>
1、**贪心解码**：每一步选概率最高的 token。简单、可复现，但容易重复啰嗦、缺乏多样性<br>
2、**Beam Search**：每一步保留 Top-B 条候选路径（B=4、8 等），最后选总概率最高的整条序列。

随机性策略：<br>
1、**Temperature 采样**：通过缩放概率分布的「锐度」，控制随机性强度。Temperature 越低越确定，越高越发散<br>
2、**Top-K 采样**：每步只从概率最高的 K 个 token 里采样，截断长尾<br>
3、**Top-P（Nucleus）采样**：每步累加概率到 P 为止，从这个「核」里采样，自适应截断

评判标准：<br>
1、任务有标准答案 -> 贪心或 Temperature=0<br>
2、任务有多种合理答案，要稳一些 -> Top-P=0.9 + Temperature=0.7<br>
3、任务鼓励多样性 -> Top-P=0.95 + Temperature=1.0+

# KV Cache 是什么？
KV Cache 是「**单次推理内**」的优化。自回归生成时，每次生成新 token 都要让模型重新对前面所有 token 算 attention。

如果每次都从零开始算，N 个 token 的总计算量是 O(N³)，根本不可接受。

KV Cache 把前面所有 token 的 K 和 V 矩阵缓存在 GPU 显存里，每次新 token 只算自己的 Q、K、V，然后跟缓存的 K/V 做 attention，把总计算量从 O(N³) 降到 O(N²)。

# Prompt Caching 的原理是什么？
Prompt Caching 是「**跨请求**」的优化。把上面 KV Cache 的概念从「单次生成内」扩展到「不同请求之间」。

如果两个请求的 Prompt 前缀**完全相同**（比如都用同样的 System Prompt），第一个请求算完的 KV Cache 在 API 服务器上保留下来，第二个请求遇到相同前缀直接跳过计算、复用已有 KV Cache，只算新增的部分。

Claude（Anthropic）：显式标记缓存断点。显式告诉 API「我希望缓存到这里」。在希望缓存的内容末尾加一个 cache_control 标记

OpenAI：自动缓存。只要请求中的 Prompt 前缀超过一定长度（1024 tokens），系统会自动尝试缓存。命中时不需要额外操作，API 响应里会告诉你有多少 token 命中了缓存。

# 适用Prompt Caching的场景
1、固定 System Prompt 的应用<br>
2、基于同一份长文档的多次问答<br>
3、大量 Few-shot 示例

# 大模型量化是什么？INT8/INT4/AWQ/GPTQ 怎么选？
**量化**（Quantization）的本质是把模型参数从「高精度浮点数」（FP32 或 FP16）映射到「低精度整数」（INT8 或 INT4），用更少的比特表示同样的信息。

**精度维度**：FP16 -> INT8 -> INT4 -> 更激进的 NF4 / FP8 等。位数越少越省，但精度损失越大。INT4 是当前的甜蜜点，效果接近 FP16，体积只有 1/4。

**算法维度**：<br>
1、**GPTQ**：基于「误差补偿」的逐层量化。每量化一层权重，用一小批校准数据测出量化误差，把误差补偿到下一层去<br>
2、**AWQ**：基于「激活感知」的权重保护。核心洞见是「**不是所有权重都同样重要**」，那些和激活值大的输入相关的权重要保护好，其他的可以激进压缩。

**怎么选**：
1、部署生产环境、看重推理速度：优先评估 AWQ / GPTQ / FP8 / 框架原生 INT4<br>
2、部署生产环境、追求最高精度：GPTQ INT4 或 FP16<br>
3、个人微调、消费级 GPU：QLoRA NF4<br>
4、极端压缩（边缘设备）：INT3 GPTQ 或 GGUF 的 Q4_K_M

# 如何写好 Prompt？
写好 Prompt 核心就是做好五件事：给模型设定角色、说清楚任务、交代背景上下文、约定输出格式、提供示例。

# 大模型为什么会出现幻觉？怎么缓解？
出现幻觉的原因：<br>
1、训练数据层面：互联网语料本身就有错误、矛盾、过时的信息，模型把这些都「学进去」当作事实记忆。<br>
2、生成机制层面：LLM 本质是「按概率续写下一个 token」，不是「查询知识库」。模型对「自己知不知道某件事」没有显式信号，碰到不熟悉的问题，会按训练时见过的相似上下文「编一个看起来合理的答案」。<br>
3、对齐目标层面：SFT 和 RLHF 训练时，「自信地回答」往往比「我不知道」得分更高，模型被无形中训练成了「不会拒答」。

缓解方案：<br>
1、训练层：对齐数据里专门加入「不知道就说不知道」的样例，做校准（Calibration）训练，让模型学会拒答<br>
2、推理层：让模型先做必要的分步分析再答（最终可以只展示简要依据）、Temperature 调低减少随机偏差、Self-Consistency 多次采样投票（错误答案不一定容易收敛）、约束解码（限制只能输出特定 vocabulary）。<br>
3、系统层：RAG 接入外部知识库（让模型「看着资料答」而不是「凭记忆答」）、答案后处理核查、强制带引用来源。

# MoE 混合专家模型是什么？DeepSeek V3、Qwen 为什么用 MoE？
MoE（Mixture of Experts，混合专家模型）的核心思想是把传统 Transformer 中的 FFN（前馈网络）层替换成 N 个并行的「专家网络」，再加一个 Router 来决定每个 token 进哪个专家。

三个核心组件：<br>
1、**多个专家（Experts）**：把 Transformer 每层的 FFN 复制 N 份（典型 N=8、64、256），每份就是一个独立的「专家」，在训练中各自学到不同的「擅长方向」（语言、代码、数学、知识等）<br>
2、**Router（路由器）**：每个 token 进到 MoE 层时，Router 算一个「专家偏好分数」，决定这个 token 该去哪个专家。<br>
3、**负载均衡**：训练时要加辅助损失防止「专家不平衡」（Router 偏爱某几个专家，其他专家没被训过），保证所有专家都在学

为什么 DeepSeek V3、Mixtral、部分 Qwen 模型都在用 MoE？<br>
1、训练性价比高：同样算力下训出来的 MoE 模型，效果接近一个大 Dense 模型，但参数总量是 Dense 的 5-20 倍<br>
2、推理成本可控：每个 token 只用一小部分参数，推理速度和小 Dense 模型相当<br>
3、可扩展性强：要增加模型容量，加专家数比加层数容易
